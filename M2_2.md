# M2.2 — Controlled no-LLM / Qwen / shuffled-knowledge experiments

## Goal and interpretation

Compare on the **same** input CSV, fixed random seed, group-by-(city,image_name)
training/validation partition, epoch budget, and final held-out evaluation files.

- `no-llm`: image CNN + geography + task encoding + latent MoE router, no Qwen
- `qwen3vl-latent`: same backbone plus correctly matched frozen Qwen hidden states
- `shuffled-latent`: same architecture/Qwen weights as qwen3vl-latent,
  but knowledge is sampled from another example in the **same dataset split**
  using a reproducible fixed derangement; images/labels for predictions stay unchanged.
  This is a negative-control intervention, **not** a knowledge-free baseline.

No-LLM has fewer trainable parameters (no latent adapter), so it is an
architecture-ablation baseline, not perfectly parameter-count-matched.
Shuffled and true latent use matching parameter counts.

These are research prototypes, not benchmark results. The code has not been
validated on MI250X in this commit.

## Pilot on exactly the same training rows

Replace /path/to/train.csv and image root with real paths.
Use different output directories per model.

```bash
for MODE in no-llm qwen3vl-latent shuffled-latent; do
  python -u run_m2.py train \
    --train-csv /path/to/train.csv \
    --image-root /flash/project_462001391/xiyanxin/Urban_experience/output_files \
    --provider "$MODE" --model-id Qwen/Qwen3-VL-2B-Instruct \
    --seed 42 --limit 1000 --epochs 3 --batch-size 2 \
    --output "runs/m22_${MODE}" --cache-dir runs/qwen_cache
done
```

The same `--seed` and `--limit` produce the same tile-group split.
Use `--resume` only with the same run configuration. Do not choose model
hyperparameters or checkpoints using SCUI/UCSI/UCUI performance.

## Independent final evaluation

```bash
for MODE in no-llm qwen3vl-latent shuffled-latent; do
  python -u run_m2.py evaluate \
    --checkpoint "runs/m22_${MODE}/best.pt" \
    --train-csv /path/to/train.csv \
    --scui-csv /path/to/scui.csv \
    --ucsi-csv /path/to/ucsi.csv --ucui-csv /path/to/ucui.csv \
    --image-root /flash/project_462001391/xiyanxin/Urban_experience/output_files \
    --seed 42 --limit 100 --batch-size 2 \
    --output "runs/m22_eval_${MODE}" --cache-dir runs/qwen_cache
done
```

**Caution:** `--limit 100` selects the first 100 rows in each test CSV, which is
not a representative random sample; it is only for integration testing.
For publication-grade results remove the limit and evaluate the same frozen
complete test sets, ideally for multiple training seeds.

Qwen frozen feature caching is keyed by image + task + model identifier. Cache
may be shared across true- and shuffled-latent runs. No target labels are ever
sent to Qwen. Shuffled source vectors are fixed per partition and seed.

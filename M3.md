# M3: Frozen RemoteCLIP -> Projector -> Region–Task MoE

M3 is an **independent** experiment. M2 stays unchanged. No M2 checkpoint can be
loaded into M3; you must train new M3 best.pt models. M3 contains 3 comparable modes:
`no-llm`, `qwen3vl-latent`, `shuffled-latent`.

## Install for the precompute stage

```bash
pip install open-clip-torch huggingface-hub
```

RemoteCLIP pretrained weights come from the official `chendelong/RemoteCLIP`
Hugging Face repo. Default is `ViT-B-32` (512-d CLIP embedding); optional
`ViT-L-14` (768-d). Weights are **strictly loaded and frozen**.
The image preprocess pipeline is the pretrained OpenCLIP pipeline, not the
M2 CNN preprocessing. For offline clusters, use
`--remoteclip-checkpoint /path/to/RemoteCLIP-ViT-B-32.pt`.

## 1. Precompute images once across all partitions

```bash
python -u run_m3.py precompute \
  --train-csv /path/train.csv \
  --scui-csv /path/scui.csv --ucsi-csv /path/ucsi.csv --ucui-csv /path/ucui.csv \
  --image-root /flash/project_462001391/xiyanxin/Urban_experience/output_files \
  --remoteclip-model ViT-B-32 \
  --feature-dir runs/m3_features --batch-size 64
```

Cache: `runs/m3_features/remoteclip_features.sqlite3`. One feature per
unique image, irrespective of target task or CSV repetition; image metadata
and encoder ID are part of the key. Never caches labels/predictions.
Interrupt and restart safely: only missing features are recomputed.

## 2. Train 3 new checkpoints

Use exactly the same training data, seed, split settings and feature store.
`--batch-size 128` is a reasonable initial option; reduce if needed.

```bash
for MODE in no-llm qwen3vl-latent shuffled-latent; do
  python -u run_m3.py train \
    --train-csv /path/train.csv \
    --image-root /flash/project_462001391/xiyanxin/Urban_experience/output_files \
    --feature-dir runs/m3_features --cache-dir runs/qwen_cache \
    --provider "$MODE" --limit 5000 \
    --epochs 20 --patience 6 --batch-size 128 \
    --seed 42 --output "runs/m3_${MODE}"
done
```

For a fair reproduction with M2.3's optimization budget, use the same training
batch size (2); a larger batch changes gradient updates per epoch and may
require retuning learning rate. This option is a new M3 experiment, not a
controlled one-variable backbone replacement.

## 3. Evaluate separate protocols

```bash
for MODE in no-llm qwen3vl-latent shuffled-latent; do
  python -u run_m3.py evaluate \
    --checkpoint "runs/m3_${MODE}/best.pt" \
    --train-csv /path/train.csv \
    --scui-csv /path/scui.csv --ucsi-csv /path/ucsi.csv --ucui-csv /path/ucui.csv \
    --image-root /flash/project_462001391/xiyanxin/Urban_experience/output_files \
    --feature-dir runs/m3_features --cache-dir runs/qwen_cache \
    --eval-batch-size 256 --seed 42 \
    --output "runs/m3_eval_${MODE}"
done
```

Evaluation uses cached RemoteCLIP vectors and **does not open PNG image data**.
If Qwen cache misses, Qwen still must open source PNG and perform its
multimodal forward, since its conditioned representations differ from RemoteCLIP
visual embeddings. No-LLM never loads Qwen.

M3 image embeddings are stored as normalized FP16, reloaded FP32. Projector,
task/context encoders, experts and router all train. The RemoteCLIP encoder
does not train. The original M2 small CNN remains an independent baseline.

## Checks

```bash
python -m unittest discover -s tests -p 'test_m3.py' -v
```

`--limit` applies to CSV loading in all three commands. Use no `--limit`
for full test sets. Validation splits are by unique city/tile from training
data only, and the train-city/train-task leakage checks are retained for evaluation.

**Caution:** frozen features are global and not guaranteed to retain local
patch-level features. The impact on SCUI/UCSI/UCUI must be tested empirically.
If you change the RemoteCLIP checkpoint while keeping the same model name,
choose a fresh `--feature-dir` so features cannot be mixed.
